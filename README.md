# World Hemp History (hemp.pi)

世界の麻(ヘンプ)にまつわる最新ニュース・歴史タイムライン・企業/プロダクト紹介を1つにまとめたPi Networkアプリです。将来的に `hemp.pi` ドメインへの紐付けを想定しています。

## 構成

```
world-hemp-history/
├── public/
│   ├── index.html       # フロントエンド(ニュース・タイムライン・企業紹介・Pi決済フロー)
│   ├── admin.html       # 管理画面(掲載の一覧・ステータス変更・削除、ADMIN_TOKENで保護)
│   ├── privacy.html     # プライバシーポリシー(日本語/English切替、単独ページ)
│   └── terms.html       # 利用規約(日本語/English切替、単独ページ)
├── scripts/
│   ├── fetchNews.js          # NewsData.io からヘンプ関連ニュースを取得しDBへ保存
│   ├── migrateJsonToDb.js    # (旧バージョン向け) data/*.json → DB への一度きりの移行スクリプト
│   └── backupDbToJson.js     # DB → data/*.json への手動バックアップ(Free Postgres対策。下記参照)
├── data/
│   ├── news.json          # (旧バージョンの名残。現在は使用しない。移行スクリプトの入力にのみ使う)
│   └── companies.json     # 同上
├── db.js                   # データストア(PostgreSQL)アクセス層
├── server.js                # Express本体。API + 自動更新スケジューラ
├── package.json
└── .env.example
```

## セットアップ

1. Node.js 18以上をインストール
2. 依存パッケージをインストール

   ```bash
   npm install
   ```

3. `.env.example` を `.env` にコピーし、値を設定

   ```bash
   cp .env.example .env
   ```

   - `DATABASE_URL`: **必須。** ニュース・企業掲載データの保存先(PostgreSQL接続文字列)。**[Neon](https://neon.tech)の無料プラン(期限切れ無し)を推奨**しています(詳細は下記「デプロイ」→「データの永続化について」参照)。未設定のままだと `/api/news` `/api/companies` 系のAPIはすべてエラーになります
   - `NEWSDATA_API_KEY`: [newsdata.io](https://newsdata.io/) で無料登録して取得(無料枠は1日200クレジット、商用利用可)
   - `TRANSLATE_EMAIL`: **実質必須。** [MyMemory Translation API](https://mymemory.translated.net/) 用。未設定でも動作はするが、匿名利用の無料枠(1日5,000文字)は1回のニュース更新だけでほぼ使い切ってしまう可能性が高いため、必ずメールアドレスを設定することを推奨(下記参照)
   - `PI_API_KEY`: Pi Developer Portalで取得するAPIキー。**Pi決済のapprove/complete処理で実際に使用します**(未設定だと決済APIがエラーを返します)
   - `PI_SANDBOX`: `true`(既定・Piのテストネット/Sandboxモードで動作)、または `false`(本番。実際のPiが動きます)。フロントエンドは `/api/config` 経由でこの値を読みに行くため、**コードを一切編集せずに切り替え可能**です
   - `NEWS_FETCH_INTERVAL_DAYS`: ニュース自動更新の間隔(日数、デフォルト3日)
   - `ADMIN_TOKEN`: 管理APIおよび管理画面(`/admin.html`)用のシークレット。第三者に推測されにくいランダムな文字列にしてください

4. 起動

   ```bash
   npm start
   ```

   `http://localhost:3000` で確認できます。

## ニュース自動更新の仕組み

- `server.js` が毎日03:00にチェックし、前回更新から `NEWS_FETCH_INTERVAL_DAYS` 日が経過していれば `scripts/fetchNews.js` を実行してニュースを取得します。
- サーバー起動時、一度もニュースが取得されていなければ即座に初回取得を行います。
- 手動で更新したい場合:

  ```bash
  npm run fetch-news
  ```

  または管理APIを呼び出す:

  ```bash
  curl -X POST http://localhost:3000/api/news/refresh -H "x-admin-token: <ADMIN_TOKEN>"
  ```

- 検索クエリは `scripts/fetchNews.js` 内の `QUERY` 定数で調整できます。嗜好用大麻のニュースをできるだけ避け、産業用ヘンプ(繊維・建材・食品・バイオ素材など)に寄せた語句にしてあります。

## ニュースの多言語対応(無料翻訳)

NewsData.ioから取得した記事(英語)は、[MyMemory Translation API](https://mymemory.translated.net/) を使って ja / zh / ko / es に自動翻訳し、`data/news.json` の各記事に `i18n` フィールドとして保存されます。フロントエンドは選択中の言語に応じて `i18n[lang]` を表示し、翻訳がない場合は英語原文にフォールバックします。

- **完全無料・APIキー登録不要**です(クレジットカード登録も不要)。
- 匿名利用は1日5,000文字まで無料。`.env` の `TRANSLATE_EMAIL` にメールアドレスを設定すると1日50,000文字まで拡大します(いずれも無料枠)。
- **1回の更新記事数は8件**(`scripts/fetchNews.js` の `ARTICLES_PER_FETCH`)。記事1件(タイトル+概要)を4言語に翻訳すると1件あたり約600〜1,000文字消費するため、8件では1回の更新で約4,800〜8,000文字を使う計算になります。**`TRANSLATE_EMAIL` を設定していないと、匿名枠(1日5,000文字)を1回の更新だけで超える可能性があります**(超えても処理は止まらず、該当言語は英語原文にフォールバックしますが、多言語表示が機能しなくなるので、必ずメールアドレスを設定してください)。
- 翻訳は取得時に一度だけ行い `news.json` にキャッシュするため、ページを閲覧するたびに再翻訳されることはありません。
- 翻訳が失敗した場合(レート制限など)は、当該言語の記事は英語原文にフォールバックして表示されます。処理は止まりません。
- より高品質な翻訳が必要になった場合は、`scripts/fetchNews.js` の `translateText` 関数をDeepL API等に差し替えることで対応できます(ただし有料になります)。

## 企業・プロダクト紹介コーナー

- カテゴリー: 繊維・アパレル / 食品 / 建材 / 化粧品・スキンケア / CBD・ウェルネス製品 / バイオプラスチック・工業素材
- 掲載料: **10π / 2ヶ月(60日)**
- 任意でロゴ画像URL(外部にホストされた画像へのリンク)を登録できます。ファイルアップロード機能ではありません(画像バイナリの保存先を別途用意する必要があるため)。読み込みに失敗した画像は自動的に非表示になります。
- 掲載申込 → Pi認証(`Pi.authenticate`)→ Pi払い(`Pi.createPayment`)→ サーバー側で approve/complete → 掲載が60日間有効化、という流れです。
- `server.js` 内の `/api/payments/approve` と `/api/payments/complete` は、Pi Platform API (`https://api.minepi.com/v2/payments/...`) を `PI_API_KEY` を使って実際に呼び出す実装になっています。`PI_API_KEY` が未設定の場合はエラーを返します。
- **支払い内容の検証**: approve/complete前に、Pi Platform APIから実際の支払い内容(`GET /payments/{id}`)を取得し、(1)金額が10πと一致するか、(2)支払い時のmetadataが対象の掲載IDと一致するか、(3)同じ支払いIDが他の掲載に使い回されていないか、(4)支払った人と申し込んだ人が同一Piユーザーか、をサーバー側で確認してから処理しています。以前のバージョンはクライアントから送られた値をそのまま信用していたため、他人の掲載を不正に有効化できてしまう可能性がありましたが、この検証により塞いでいます。
- **申込者の記録**: 掲載申込み時に `Pi.authenticate(['username','payments'])` でPi認証を行い、取得したアクセストークンをサーバー側で `/v2/me` により検証した上で、申込者のPiユーザー名・UIDを掲載データに記録します(上記(4)の本人確認にも使用)。Pi Browser以外で開いた場合など認証できない場合は掲載自体は作成されますが、その場合(4)の本人確認は行われません。
- 掲載フォームの入力(名前・説明・URL等)には文字数上限とURL形式(http/https以外を拒否)のバリデーションを追加しています。表示側でもHTMLエスケープ・URLスキームの再チェックを行っています。
- 掲載期限が切れたものは毎日自動で「期限切れ」ステータスに変わります。また、支払いが完了しないまま24時間以上放置された申込みは自動的に削除されます(データが際限なく溜まるのを防ぐため)。
- 掲載申込みのAPI(`POST /api/companies`)には、同一IPからの連続送信を防ぐレート制限(15分あたり8件)を設けています。
- 掲載の事前審査(モデレーション)フローはありません。支払いが完了すると即座に公開されます。不適切な掲載は下記の管理画面から事後的に停止・削除してください。

## 管理画面(`/admin.html`)

デプロイ後、`https://<デプロイ先ドメイン>/admin.html` にアクセスすると、`.env` の `ADMIN_TOKEN` でログインできる簡易管理画面が使えます。

- 掲載申込み(支払い待ち・掲載中・期限切れ・停止中すべて)を一覧表示
- 各掲載のステータスを手動で変更(不適切な掲載の「停止」、誤って期限切れになったものの「復活」など)
- 掲載の完全削除
- 「ニュースを今すぐ更新」ボタン(`/api/news/refresh` を呼び出します)

**注意**: `admin.html` 自体は(他の静的ファイルと同様)URLを知っていれば誰でも開けますが、中のデータ操作はすべて `ADMIN_TOKEN` を知らないと失敗するようになっています。`ADMIN_TOKEN` は第三者に推測されにくいランダムな文字列にし、このURLも不用意に共有しないでください。管理者トークンはページを閉じる・リロードすると消え、ブラウザに保存されません。管理API(`/api/admin/*`、`/api/news/refresh`)には15分あたり60件のレート制限もかけており、`ADMIN_TOKEN`の総当たり試行を多少遅くします。

## セキュリティ・運用面の対策(2026年9月時点)

- **レート制限**: 掲載申込み(`POST /api/companies`)は15分あたり8件、管理API系は15分あたり60件までに制限しています。IPアドレス単位・サーバーのメモリ上でカウントする簡易実装のため、サーバー再起動でリセットされ、複数インスタンス構成では共有されません(その規模になった場合はRedis等の外部ストアへの切り替えを検討してください)。
- **セキュリティヘッダー**: `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / `Content-Security-Policy` を付与しています。**ただし正直に書いておくと**、`public/*.html` は単一ファイル内にインラインの `<script>` を書く構成のため、CSPの `script-src` は `'unsafe-inline'` を許容せざるを得ず、XSS対策としての実効性は限定的です(本質的なXSS対策は各ページでのHTMLエスケープ・URLスキーム検証で行っています)。厳密なCSPを効かせたい場合は、インラインスクリプトを外部ファイル化してnonceを使う構成への作り替えが必要です。
- **ヘルスチェック**: `GET /healthz` でDB疎通を含めた簡易ヘルスチェックができます。RenderのHealth Check Pathにこのエンドポイントを設定すると、デプロイ時の切り替わりが安定します。
- **グレースフルシャットダウン**: Renderがデプロイ時に送るSIGTERMを受けて、cronジョブの停止・HTTPサーバーの停止・DBコネクションプールのクローズを行ってから終了するようにしています。

## デプロイ

飲食.Piと同様、Render(無料枠)へのデプロイを想定しています。DB(PostgreSQL)は下記の通りNeonなど別サービスに切り出す構成を推奨していますが、Webサービス自体はこれまで通りRenderで問題ありません。

1. GitHubリポジトリを作成しpush
2. Renderで新規Web Serviceを作成し、このリポジトリを接続
3. Build Command: `npm install` / Start Command: `npm start`
4. 環境変数(`.env`の内容、`DATABASE_URL`含む)をRenderのEnvironment設定に登録
5. Pi Developer Portalでドメイン検証・PiNetサブドメイン設定を行う(hemp.pi紐付けはPiのOpen Network展開状況に応じて後日対応)

### データの永続化について(重要)

以前のバージョンはニュース・企業掲載データを `data/news.json` / `data/companies.json` という2つのファイルに直接保存していました。しかしRenderの無料プラン(および Persistent Disk を付けていない有料プラン)はディスクが一時的(ephemeral)で、再デプロイやコンテナの再起動のたびにファイルシステムがリセットされてしまいます。企業の掲載データは実際にPiの支払いが発生しているデータなので、これが再デプロイのたびに消えるのは避けたいところでした。

そのため、このバージョンから **PostgreSQLにデータを保存する構成**に変更しています(`db.js`)。標準的なPostgreSQLであれば接続文字列(`DATABASE_URL`)を設定するだけでどのホスティング先でも動くので、コードは一切変更せずにDB側だけ切り替えられます。

#### 推奨: Neon(無料・期限切れなし)

RenderのFree PostgreSQLは**作成から30日+14日の猶予期間で自動的にデータが完全削除される**仕様です(2026年9月時点。バックアップ機能も無し)。調べ直した結果、[Neon](https://neon.tech)というPostgres専門のホスティングサービスの無料プランは、**「Free plan is permanent (not a trial); no credit card required.」と公式に明言されており、期限切れでデータが削除される仕組みがありません**。ストレージも0.5GBまで無料で、このアプリの規模(掲載データ+ニュースキャッシュのみ、画像はURLリンクのみで実体を保存しない)なら十分すぎるほどです。そのため、こちらを標準の構成として案内します。

設定手順:

1. [neon.tech](https://neon.tech) でアカウントを作成する(無料、クレジットカード不要)
2. 新規プロジェクトを作成する
3. ダッシュボードの「Connect」から接続文字列(Connection string)をコピーする。「Pooled connection」(ホスト名に `-pooler` を含むもの)がアプリ用途の既定として案内されているので、通常はそちらを使えばよい。形式は `postgresql://<user>:<password>@<host>-pooler.<region>.aws.neon.tech/<dbname>?sslmode=require&channel_binding=require` のようになる
4. `.env`(またはRenderのEnvironment設定)の `DATABASE_URL` にこの接続文字列をそのまま設定する。`DATABASE_SSL` は変更不要(既定でSSL接続になる)
5. 再デプロイする。起動時に `server.js` が必要なテーブルを自動作成するので、追加の初期化作業は不要

   接続文字列に含まれる `channel_binding=require` は、Node.jsの `pg` ライブラリでは特に意識する必要のない(未対応のまま無視される)パラメータです。万一これが原因で接続エラーになる場合は、このパラメータを取り除いて `?sslmode=require` だけにして試してください。

Web Service自体(Render)は無料プランのままで問題ありません。DBだけをNeonに切り出す構成になります。

#### 代替: RenderのFree PostgreSQLを使う場合

Renderのダッシュボード内だけで完結させたい場合は、引き続きRenderの無料PostgreSQLも使えます(「New +」→「PostgreSQL」→ 無料プランで作成 → 「Internal Database URL」を `DATABASE_URL` に設定)。ただし前述の通り**作成から30日+14日でデータが自動削除される**ため、この方法を選ぶ場合は次項の「定期バックアップ」を必ず運用してください。

#### 既存データがある場合の移行手順

**既にRenderで運用中のバージョン(JSONファイル方式、またはRenderのFree PostgreSQL)から移行する場合**は、以下の手順を踏んでください。

1. JSONファイル方式からの移行の場合: Renderのダッシュボードの「Shell」機能などで、稼働中のインスタンス上の `data/companies.json` と `data/news.json` の中身を取得し、このプロジェクトの `data/` フォルダに保存する。既にPostgres(Render等)を使っている場合は代わりに `npm run backup` を実行する(下記参照)
2. 上記の手順でNeon(またはRender)のDBを用意し、`DATABASE_URL` を設定する
3. ローカル(またはRenderのShell)で移行スクリプトを実行する

   ```bash
   npm run migrate
   ```

   既にDB側に存在するIDはスキップされるため、複数回実行しても安全です。
4. 移行完了を確認してから、新しいコード(このバージョン)をデプロイする

新規にデプロイする場合(まだ実データが無い場合)は、上記の移行手順は不要です。`data/*.json` の2ファイルはこの移行スクリプトの入力としてのみ使われ、アプリの動作には一切関与しません(削除しても問題ありません)。

#### 定期バックアップ(どのDBを使う場合でも推奨)

Neonのように期限切れが無いサービスであっても、無料枠に自動バックアップが付いていないことに変わりはありません。誤操作やサービス側の障害に備え、1〜2週間に一度を目安に、DBの内容を手元のファイルに書き出しておくことを引き続き推奨します。

```bash
npm run backup
```

`data/companies.json` / `data/news.json` に現在のDB内容が書き出されます。**このコマンドを実行しただけでは不十分**で、書き出されたファイル自体をDBとは別の場所(このリポジトリのGitコミット、手元のPCへの保存など)に必ず保管してください。万一データが失われた場合は、このバックアップファイルを `npm run migrate` で新しいDBに読み込むことで復元できます。

### 本番でPi決済を有効にする

1. `.env` の `PI_API_KEY` に、Pi Developer Portalで取得したAPIキーを設定する
2. 動作確認が済んだら、`.env` の `PI_SANDBOX` を `false` に変更する(コードの編集は不要です。フロントエンドは起動時に `/api/config` からこの値を取得します)
3. Renderの環境変数にも同じ値を反映して再デプロイする

`PI_SANDBOX` を `true`(既定値)のままにしておくと、Pi SDKは常にテストネット/Sandboxモードで動作し、実際のPiは動きません。動作確認が終わるまでは `true` のままにしておくことを推奨します。

## サイト構成(2026年9月改訂)

コンテンツの厚みと信頼性を補強するため、以下のセクションを追加しています。

- **数字で見る産業用ヘンプ**(ヒーロー直下の統計バンド): 市場規模・CAGR・CO2吸収量・主要生産国を出典付きで表示。出典は Grand View Research (Industrial Hemp Market, 2025) および Darshil Shah / Cambridge Centre for Natural Material Innovation(Dezeen, 2021経由)。数値は `public/index.html` 内の `STATS` 定数、および `artifact/preview.html` の同名定数にハードコードされています。将来的に数値を更新する場合は両ファイルを同時に編集してください。
- **企業ディレクトリのCTA刷新**: 掲載企業がまだ無い「コールドスタート」状態を隠すのではなく、「最初の掲載企業になりませんか?」という"ファウンディングメンバー"訴求に変更し、市場成長率・多言語リーチ・低価格の3つのベネフィットを箇条書きで提示しています。**実在しない企業を "サンプル" として掲載するようなことはしていません**(実際には存在しない企業情報を実在するかのように見せるのはユーザーの信頼を損なうため)。企業ディレクトリを充実させるには、実際の企業への掲載営業が別途必要です。
- **フッターの About / Contact / Privacy / Terms**: フッター下部の4つのリンクをクリックするとモーダルで表示されます。内容は `public/index.html` 内の `INFO_TITLES` / `INFO_BODY` 定数(5言語分)で管理しています。

- **Contact(お問い合わせ)のメールアドレスはプレースホルダーです**。`INFO_BODY` 内、および `public/privacy.html` / `public/terms.html` 内の `contact@hemp.pi` は仮のアドレスなので、実際に受信できるアドレスに差し替えてください(フッターのモーダルは5言語、単独ページは日本語/英語の切替式です)。
- **Privacy Policy / Terms of Service の文面は一般的なひな形です**。法律の専門家によるレビューを受けたものではないため、本番公開前に(特に景品表示法・特定商取引法など、掲載料を徴収するサービスに関わる日本国内法、および対象となる各国の法規制の観点から)内容を確認・修正することを推奨します。
- **企業ディレクトリの実データはまだありません**。捏造した企業情報を掲載することはしていないため、実在企業への掲載営業は別途必要です。

以下は2026年9月時点でコード側の対応が完了している項目です(参考)。

- Pi決済のapprove/complete処理(実際のPi Platform API呼び出し)
- **Pi決済の内容検証**(金額・metadata・使い回し防止・申込者本人確認)
- `PI_SANDBOX` を `.env` だけで切り替えられる仕組み(コード編集不要)
- 掲載フォームの入力バリデーション(文字数上限・URLスキーム制限)
- PostgreSQLへのデータ永続化(再デプロイでデータが消えないようにする移行。行ロックによる同時更新対策込み)
- 期限切れ掲載の自動反映、未払いpendingデータの自動削除
- 簡易管理画面(`/admin.html`)
- ニュース翻訳の文字数対策(記事数削減・`TRANSLATE_EMAIL`の実質必須化)
- レート制限、セキュリティヘッダー、ヘルスチェック、グレースフルシャットダウン
- DBの手動バックアップスクリプト(`npm run backup`)

ただし、以下はユーザー自身の対応が必要です。

- **Neon(推奨)またはRenderでPostgreSQLを作成し `DATABASE_URL` を設定する作業**(それぞれのダッシュボードでの操作が必要なため)。「デプロイ」セクションの「データの永続化について」を必ず確認してください
- **`npm run backup` の定期実行と、書き出されたファイルの別所保管**(同セクション参照)。Neonを使えば期限切れによるデータ削除は避けられますが、無料枠に自動バックアップが無い点はどのサービスでも共通のため、このバックアップ運用は引き続き推奨します

## Pi Developer Portalへの登録(Privacy Policy URL / Terms of Service URL)

Pi Developer Portalの「Develop」設定画面には、`App's Privacy Policy URL` と `App's Terms of Service URL` という、それぞれ単独のURLを入力する欄があります。フッターの情報モーダル(JavaScriptで開くポップアップ)はこの用途には使えないため、代わりに以下の単独ページを用意しています。

- `public/privacy.html` → デプロイ後は `https://<デプロイ先ドメイン>/privacy.html`
- `public/terms.html` → デプロイ後は `https://<デプロイ先ドメイン>/terms.html`

`server.js` は `express.static('public')` でこのフォルダを配信しているため、Renderなどにデプロイすれば追加設定なしにこれらのURLでアクセスできます。デプロイ後、実際のURLをPi Developer Portalの該当欄に入力してください。

※参考として、同内容をClaudeのArtifact機能でも公開しています(Pi Developer Portalの審査担当者がすぐ内容を確認できるよう、デプロイ前の暫定URLとして利用可能です。ただし共有設定を「リンクを知っている全員が閲覧可」に変更する必要があります)。本番ではデプロイ先の `/privacy.html` `/terms.html` に差し替えることを推奨します。
